What happens to one hit — the pipeline

  1. 1
    Load & formalise loaders · normalize/*
    819 hits, 440 alerts, 72,265 customers; dates (day-first), 250 countries + demonyms, name variants normalised
  2. 2
    Resolve the customer resolve · identity (SOP P2–P4)
    follow account / login / email link, else search; join holders; identity graph (phone+DOB, document no.); latest approved KYC/note = verified identity
  3. 3
    Gather hit facts facts (SOP P5)
    DOBs from dobs → profile notes → filtered web results; countries; deceased date; earliest dated report
  4. 4
    Decision core core/aml_engine
    teammate's reviewed engine + 9 Head-of-FinCrime policy calls + its own independent re-derivation of every clearance
  5. 5
    Independent rule check rules/* (SOP P6–P8)
    6 rule families → type: 1 clear / 0 agree, deceased: 4 clear / 0 agree, temporal: 22 clear / 0 agree, dob: 111 clear / 170 agree, name: 164 clear / 695 agree, location: 292 clear / 454 agree
  6. 6
    Dual-control compiler compiler.merge_with_core
    engines agree on 769/819 (94%); core clear vs check confirm → REVIEW; any other disagreement → 4-eyes
  7. 7
    Human-in-the-loop tiers triage
    auto-cleared 397 · auto-escalated 98 · borderline 58 · analyst review 266 (35 escalated by policy with a written Reviewer action)
  8. 8
    Explain & emit explain · cli · app · .grok plugin
    2–4 sentence reason, cited record IDs, customer id → output/dev.jsonl; dashboard case file; Grok plugin narrates (never decides)

Rule base: SOP principles P1–P9 and its 11 reason codes, 9 Head-of-FinCrime policy calls, 2 dual-control rules. External typology sources (FATF, NCA, OpenSanctions) are context only and never change a decision.
